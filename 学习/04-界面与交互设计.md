# 04 · 界面与交互设计 —— 「学习」页面

> 用户划定的边界：**先忽略对话框**，把整个软件界面与交互想清楚、实现出来，再调整。
> 本文是设计说明；可点的实现在同目录 `index.html`（原型即本设计的实现）。

---

## 一、设计目标（三条，全部来自需求）

1. **一眼看到全部知识点** —— 打开页面，小学数学 92 个知识点全部在场，不用去别处找。
2. **一眼看到对照关系** —— 题目与知识点之间能互相高亮、互相跳转；「全部对照关系」一键展开。
3. **作答即诊断** —— 答完自动判分，错的题反向标记出薄弱知识点，点开就是讲解（反向教学）。

外加两条体验目标：**闯关的趣味性**（解锁、能量石、点亮灯塔）与**记录可保存**（进度、错题、导出）。

---

## 二、在软件中的位置（未来接线，本轮不做）

```
Wanna 导航栏
├── 对话（现有，完全不变：图文/语音/视频、输入框、输入框上方控件）
├── …（现有各项）
└── 「学习」页（新增）← 本次设计的对象
      ├── 页面内容 = 下面的三栏界面（可整体滚动）
      ├── 对照关系抽屉 = 可隐藏（默认收起，点「全部对照关系」展开）
      └── AI 对话窗（未来）= 完整的对话窗口叠在页面里，同样可隐藏
            · 图文、音频、视频、输入框、输入框上方控件全部保留
            · 作用：AI 出题判定、答错后的讲解、对话记录保存
```

**原则**：学习页是**新增的一个页面**，不动现有对话窗口的任何东西；页面内所有辅助窗口
（对照抽屉、未来的 AI 对话窗）都必须**可隐藏**，主内容永远完整可读。

```
│              │ ┌─ 第 3 关 · 架桥运粮（三年级）LOCK ┐ │                     │

│   …          │ │ 3-2 …                             │ │  ↕ 对应              │

```

| 区域 | 职责 | 关键交互 |
|---|---|---|
| **顶栏** | 身份 + 进度 + 掌握度 + 全局动作 | 7 个进度节点点击直达对应关卡；「全部对照关系」开合右栏 |
| **左栏 · 知识地图** | 全部 92 个知识点按年级分组陈列，**状态一眼可见** | 点知识点 → 弹出讲解卡 + 跳到对应题目并高亮；可折叠成窄条 |
| **中栏 · 关卡主线** | 唯一的作答区：故事 → 小题 → 能量合成 → 解锁 | 每题：作答 + 检查 + 提示；能量对 → 解锁下一关 |
| **右栏 · 对照关系抽屉** | 题目 ↔ 知识点的**双向映射表**，「全部对照关系」的落点 | 按关卡/按知识点两种排法；点任一侧，另一侧高亮并可跳转 |

## 四、核心交互（五个流程）

### 4.1 闯关流（主流程）

```
进入第1关 → 读故事 → 逐题作答[检查] → 全关小题完成 → 能量合成
   ├─ 算对 → 获得能量石 🔓 自动解锁下一关，左栏对应知识点变绿
   └─ 算错 → 标红，并提示「哪几题的答案参与了合成」（点进去改）
第7关密码正确 → 灯塔点亮（整页庆祝动画）→ 出总诊断报告
```

- **链式硬约束**：未解锁关卡显示为锁定态（题目灰显、不可作答），但**故事与知识点清单可见**
  ——地图永远完整，这是需求第 1 条。
- 解锁判据 = 能量合成题算对（能量数写死为标准值，保证链条稳定）。

### 4.2 提示流（提示给知识，不给答案）

每题旁有「提示」按钮 → 展开该题所考察**知识点的名称 + 一句话讲解**：

> 例：3-1 的提示 = 「时、分、秒：1 时 = 60 分；算经过时间：结束时刻 − 开始时刻」

**不出数字、不给答案** —— 先补知识，再回来解题（需求：对照关系「同时是提示或暗示」）。

### 4.3 诊断流（作答即检测）

- 判错的题 → 其全部考察知识点标为 **✗ 待巩固**（左栏变琥珀色）。
- 判对的题 → 对应知识点标为 **✓ 已掌握**（绿色）；未作答 = 灰色。
- 「诊断报告」弹层：按年级分组列出薄弱知识点 → 每条带讲解 + 「跳到题」按钮 →
  点过去重做那道题 → 做对则该知识点转绿。**整个闭环不离开这一页。**

### 4.4 对照流（全部对照关系）

点顶栏「全部对照关系」→ 右栏抽屉展开：

- **按关卡**：一关一张表，每行 = 题干片段 ↔ 知识点 chips；
- **按知识点**：92 个点逐条列出 ↔ 对应题号；
- **双向高亮**：点知识点 → 中栏所有相关题目描边高亮并滚动到位；点题目 → 抽屉里对应条目与左栏 chip 同步高亮。
- 抽屉随时可关（**窗口可以隐藏**），中栏不受影响。

### 4.5 记录与导出流

- 每次作答即时写入 localStorage：`answers / results / 解锁进度 / 能量数`；
- 「导出记录」下载 JSON（学生答卷 + 诊断结果），满足「过程记录全都保存下来」；
- 「重置」清空（需二次确认）；「演示模式」一键解锁全部关卡并显示标准答案，供家长/老师浏览全题与全映射。

## 五、状态设计（元素级）

| 状态 | 左栏知识点 chip | 中栏题目 | 关卡头 |
|---|---|---|---|
| 未接触 | 灰 | 待作答（输入框可用） | 进行中 |
| 答对 | 绿 ✓ | 绿框 + 显示对勾 | 完成 |
| 答错 | 琥珀 ✗（待巩固） | 红框 + 正确答案提示可展开 | 进行中 |
| 关卡未解锁 | 照常显示（地图完整） | 灰显不可作答 | 🔒 锁定 |
| 能量合成通过 | — | — | 🔓 能量石点亮 + 下一关解锁 |

规则：**知识点状态只由作答结果驱动**，不由关卡解锁驱动（看得见 ≠ 会做）。

## 七、未来接 AI 对话的接入位（本轮只留接口，不实现）

1. **位置**：学习页内的浮动对话窗（完整对话窗口：图文/音频/视频/输入框/控件），顶栏「AI 对话」按钮开合，默认隐藏。
2. **职责分担**：
   - 静态判分（填空/选择）→ 页面本地做，零延迟；
   - **需要过程性判断的**（解题步骤说理、表达类回答）→ 发给 AI 判定，判定结果回写为该知识点的 ✓/✗；
   - 答错后的讲解 → 优先用知识点自带的 `tip`，不够再让 AI 展开讲；
   - 对话记录 → 与作答记录一起进导出 JSON。
3. **数据契约**：页面已有 `kpId / itemId / correct / weak[]` 结构，AI 侧只需回写
   `{kpId, result}`，不改界面。

## 八、为什么是这个形态（设计决策记录）

| 决策 | 理由（对应需求） |
|---|---|
| 知识点地图**常驻左栏**而不是藏进弹窗 | 「让一个人能够看到整个小学数学所有的知识点」——必须一打开就在场 |
| 对照抽屉**可隐藏** | 用户原话：「映射关系可以调整，这个窗口可以隐藏」 |
| 提示给**讲解**不给答案 | 「对照关系也可以作为提示或暗示：先把那个知识点解决掉」 |
| 判错标到**知识点**而不是只标题 | 「根据学生的错误判断出他哪一个知识点不了解」 |
| 链式解锁 + 能量合成 | 「第一阶段的结果作为第二阶段的输入……不按阶段解决可能很难实现」 |
| 演示模式 | 老师/家长需要不作答就能浏览全题与全映射 |
| 文档与原型**同源生成** | 映射关系必须可靠；手写两份必然漂移（本仓库的既有教训） |
