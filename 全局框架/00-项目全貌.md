## 三、一轮的完整工作逻辑

```mermaid
sequenceDiagram
    participant U as 你
    participant N as 刘海
    participant W as Wanna（外壳）
    participant P as Python 决策大脑
    participant H as 10 个 MCP 工具

    U->>N: 按快捷键说话
    N->>N: 录音 + 实时转写（字幕显示在刘海下）
    U->>N: 再按一次 = 发送
    N->>W: 「打开计算器，按 7」
    W->>W: 状态机 / 截图 / 历史 / 方向看板
    W->>P: 起 Python 子进程，把任务传过去
    loop 直到做完（实测 14 步 / 13 秒）
        P->>H: 调工具（如 click label="7"）
        H->>H: 三层解析：① 按名字 → ② 坐标吸附 → ③ 估算点
        H-->>P: 「界面变了：新增 2 · 消失 2」← **点完会报变了什么**
    end
    P-->>W: 最终答复（一句话）
    W->>U: 播报 + 鼠标旁卡片显示
```

### 三个关键机制

**① 三层解析是串行兜底，不是并行对比**

```
① 按名字  → 找到就返回（代码原话：根本不看估算点）
          → 没找到 ↓
② 坐标吸附（拿估算点当线索找附近的小控件）
          → 没找到 ↓
③ 直接用估算点   ← 实测命中率约 17%
```

⚠️ **③ 不是罕见路径**：仓库自己量过，7 次点击解析里 **6 次是「模型没写名字」** → 直接掉到 ③。

**耗时**：纯代码，**不是三次模型交互**。模型只被调一次；①② 各要一次 AX 跨进程
查询（实测 0.14–0.6 秒）。最坏多花一秒左右。

**② 点完会告诉你"界面变了什么"** —— 这是 2026-09-29 从 `mcp-server-macos-use`
移植过来的，也是最值钱的一件：

```
点击了「显示起始页」。界面变了：新增 0 · 消失 1 · 改动 0。
⚠️ 界面没有任何变化 —— 这一下可能没点中，或者那个控件本来就不响应。
```

在这之前只回一句「点击完成」，**调用方不知道生效没有**，于是会对着一个没发生的结果继续做。

**③ 没写名字的点击不许静默执行** —— 做不到就如实说，不假装成功。


| **工具 / MCP** | 一条命令、一个外部服务 | **代码执行** |
| **那 10 个工具** | 真正动手的手 | **Wanna 执行** |

> **决策换完了，外壳没动。** 你按快捷键说话，**拍板的是 Python 了**；
