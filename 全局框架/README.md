# 全局框架

**这个目录放的是「这个系统现在长什么样」** —— 一个子系统一篇，改它之前先读它。

2026-09-28 从 `开发经验/` 里拆出来的。拆的理由是**过期的时机不一样**：
这一层描述的是**代码的现状**，改了代码它就过期；而 `开发经验/` 里那些规律、坑、实测数字，
不会因为代码改了而失效。把两种东西放在一个目录里，结果是这一层没人更新、
读者分不清哪句是"现在的行为"、哪句是"当年的教训"。

| 目录 | 放什么 |
|---|---|
| **`全局框架/`**（本目录） | 这个系统**现在**长什么样 —— 改了哪个子系统，就顺手更新哪一篇 |
| [`../开发经验/`](../开发经验/README.md) | **学到的**：方法、坑、实测数字、复盘、事故 |
| [`../需求/`](../需求/README.md) | **用户定的契约**：交互 / 界面 / 引擎 / Harness —— 只有用户能改 |
| [`../AGENTS.md`](../AGENTS.md) | 这个 app 是什么、有哪些子系统、改代码要走什么流程（同时是 `../CLAUDE.md`，软链） |

⚠️ **序号是连着的 01–14，中间缺的 09 / 10 / 13 是故意的** —— 那三篇（实测数据 / 踩过的坑 /
顽固问题排查法）本来就是"学到的"，留在 `开发经验/` 里。别去找。

## 改这个目录的规矩

1. **改了代码就顺手改这里。** 这一层和 `开发经验/` 的区别就在这 —— 它**必须**跟着代码走，
   过期了比没有更坏（读者会照着一段不存在的描述去改）。
2. **写"现在是什么"，不写"当年为什么"。** 为什么会变成这样属于 `开发经验/`；
   这里只回答「它现在怎么工作、改它要动哪几个文件、有哪些不变量不能碰」。
3. **一篇一个子系统。** 新加一个子系统就新开一篇，并在上面的目录里加一行。
