## ① Sessions —— 官方 API（源码实测）

**接口**（`agents/memory/session.py:43`，`Session` Protocol）：

```python
async def get_items(self, limit: int | None = None) -> list[TResponseInputItem]
async def add_items(self, items: list[TResponseInputItem]) -> None
async def pop_item(self) -> TResponseInputItem | None
async def clear_session(self) -> None
```

**实现**：`agents/memory/sqlite_session.py:18` 的 `SQLiteSession`。

**用法**：`Runner.run(agent, input, session=session)`

**和我们的功能对应**（这是关键）：

| Wanna 的功能 | 官方机制 |
|---|---|
| 连续对话 | **同一个 `session` 实例**（同一个会话 id → 同一个 SQLite 文件） |
| **新建对话** | **换一个 session id**（或对同一个 `clear_session()`） |
| 会话 id 从哪来 | **用 `ConversationSession` 的 UUID string** —— 和「卡片 id = 实体 UUID」同一个做法 |

⚠️ 官方：*"Session persistence **cannot be combined** with server-managed conversation settings"* ——
一次 run 只能一种。所以**必须决定 Wanna 那边现有的"Swift 重放历史轮次"要不要撤**。
**两套并存 = 官方禁止的混用。**

## ② Subagent：复盘（官方 `Agent.as_tool()`）

官方对"用 as_tool 还是 handoff"给了一句判据：
*"Use **agents as tools** when a specialist should help with a **bounded subtask**
but should **not take over** the user-facing conversation."* → **复盘是这种。**

**签名**（`agents/agent.py:583` 实测，挑我们要用的）：

```python
review_agent.as_tool(
    tool_name="review",
    tool_description="...",
    max_turns=...,      # 子 agent 最多几步
    hooks=...,          # 生命周期钩子（③ 用）
    session=...,        # 子 agent 自己的状态
)
```

**设计（简单为主，目的是学框架）**：

```
主 agent（18 个工具 + 11 个技能）
  └─ tools 多一个：review_agent.as_tool(...)
       └─ review_agent
            · instructions ← 「复盘」技能正文
            · mcp_servers ← 第二条约 MCP 连接，带 tool_filter
                            只放 read_file / write_file / list_skills
            · 文件夹限定：Wanna复盘/
```

**"限定文件夹"用官方的 `tool_filter`**（`create_static_tool_filter`）——
这是官方文档头条级用法（*"权限控制：只读不写"*），**不是我在发明**。

## ③ Hooks —— 官方 API（源码实测）

`agents/lifecycle.py`：

```python
class RunHooksBase:      # 挂在整个 run 上
    async def on_llm_start / on_llm_end
    async def on_agent_start / on_agent_end
    async def on_handoff
    async def on_tool_start / on_tool_end

class AgentHooksBase:    # 挂在某一个 agent 上
    async def on_start / on_end
    async def on_handoff
    async def on_tool_start / on_tool_end
    async def on_llm_start / on_llm_end
```

**对我们的直接价值**：`on_tool_start` / `on_tool_end` 正好是**本地追踪要的东西**，
而且比现在"解析 span"更直接。**可能可以把 `local_trace.py` 简掉一层**
（待验证：两者是否重复 —— 若重复，**留官方那个，删我自己那个**）。
