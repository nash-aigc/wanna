# 删除 Swift 侧的 agent 逻辑（2026-09-29 用户令）

> 用户原话：「**我之前说过，完全删除 swift，全部换成 python 和官方 sdk，现在去做，
> 全部删除干净，然后不要再问我**」

## ⚠️ 先说清一件事：删的是「agent 逻辑」，不是「外壳」

**Wanna.app 本身就是 Swift** —— 刘海面板、语音采集、TTS 播放、截屏、光标的飞行、
TCC 权限、菜单栏……**这些东西官方 SDK 里没有，也没有 Python 替代品**。
把 Swift 整个删掉 = 这个 App 不存在了。

**用户要删的是"本该由官方 SDK 负责、而我们自己在 Swift 里又做了一遍"的那部分。**

判据：**这件事官方 SDK 有没有？**
- 有（记忆、决策、工具执行、子 agent、钩子、上下文策略）→ **删 Swift 的，用官方的** ✅
- 没有（刘海、语音、TTS、截屏、权限、光标）→ **留下**，那是外壳

## 一、要删的（CompanionManager 的记忆管线）

**核心判据**：这些是"**把历史喂进模型请求**"的代码 —— 官方 `Session` 接管之后它们就是重复。

| 行 | 是什么 |
|---|---|
| 233 | `historyCompressionTask` 属性 |
| 1455–1456 | 它的取消 |
| **5210** | `trimConversationHistory(toRounds:)` —— 「记住最近多少轮」的窗口 |
| **5225–5281** | 压缩任务体 —— 「历史自动压缩」把老轮次总结成摘要 |
| **5283–5307** | `persistConversationHistory*` —— ⚠️ **见下，要拆开看** |
| 3885 / 3999 / 4508–4526 | 重放相关注释与逻辑 |
| 系统提示词里的历史段 | 拼 `<history>` 那些 |

**配套要删的设置项**（9 个待核）：`记住最近多少轮对话`、`重启后保留对话`、
`历史自动压缩`、`历史里带截图`、`回答长度`、`补充指令`……（`对话与记忆` 整页要重看）

## 二、⚠️ 不能一刀切的（同一个函数里混着两件事）

`persistConversationHistory` 这个名字下面混了**两件不同的事**：

1. **喂模型的历史**（要删 —— 官方 Session 接管）
2. **给用户看的会话记录**（`ConversationSessions.json` —— 侧栏、归档页、搜索全靠它）

**第 2 件绝对不能删。** 那是产品本身，不是 agent 记忆。
删之前必须逐行读，**按"这段数据谁在读"分**，不能按函数名分。

（这也是 D55 那类事故的形状：批量删之前先看清每一行的读者是谁。）

## 三、顺序（不能乱）

1. **先接上 Swift → session-id**（`ConversationSession.id` 的 UUID 传给 `--session-id`）
   —— 不做这步就删 Swift 记忆，等于**记忆直接没了**
2. **再设 `SessionSettings(limit:)`**（对齐现有「记住最近多少轮」的默认值）
   —— 不做这步就是**历史无限增长**（默认 `limit=None` 取全部）
3. **然后才删** Swift 的窗口 / 压缩 / 重放
4. **最后删设置项**（`对话与记忆` 页）

## 四、执行方式

- **开 `wip/` 分支**（跨多文件、改可见行为 —— §0.3）
- **逐字替换，不用行区间**（D55：我用批量删把 CompanionManager 弄坏过四次）
- 每删一处 → `xcrun swiftc -typecheck` → 全绿再继续
- 删完 → 构建 → 重启 → **真跑一轮验证记忆还在**（这是唯一能证明没删错的判据）
