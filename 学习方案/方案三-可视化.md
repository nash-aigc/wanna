# 方案三 · 可视化呈现（同一道题，用「看」代替「读」）

> 状态：**第三种方案的形态研究**。题目仍是方案二那道《守灯人手记 · 第七夜》——
> 不是换一道题，而是把同一道题从「文字排版」换成**图像 / 场景 / 动画 / 游戏**。
> 交付：本 MD（设计文档）+ [`index.html`](index.html)（可交互 H5 图形界面，同目录）。

---

## 一、要解决的问题

- 方案二的题面是 800 多字的连续文字，**阅读压力大**：用户面对一大段字会本能抗拒；
- 文字是线性的，而题目本质是一张**网**（谁引用谁）——文字把网摊平成了段落，
  关联全靠读者脑内重建，这正是「看起来压力特别大」的根源；
- 目标：**让用户「看见」这道题** —— 一张图、一个场景、一段动画、一个小游戏都行，
  只要压力更低、关联更直观。

## 二、一条必须遵守的原则（用户 2026-10-02 强调）

> **不是每一个知识点对应一句话。** 有可能一句话包含三个、四个知识点，
> 才能够理解这句话、理解这个问题。如果每一句一个知识点，那就会有很多句话，
> 用户看不过来。要**交叉的、混合的、综合**的方式，以图形化呈现。

落地成三条设计律：

| # | 设计律 | 含义 |
|---|---|---|
| 1 | **混合承载** | 场景里一个物件/一个画面元素，一次承载 **3~5 个知识点**（如「地基与时钟」一张卡里同时有时钟、经过时间、速度、周长、混合运算）——绝不做「一句一点」的标注列表 |
| 2 | **关联即图形** | 知识点之间的引用关系画成**看得见的连线**（依赖线 / 计入密码线），不写成文字说明 |
| 3 | **不破坏「一道题」** | 可视化里**只有一个输入框：灯塔密码**。不给每个物件配输入框 —— 那会退回方案一的题海 |

## 三、可视化策略（从文字到图形怎么转）

1. **空间叙事替代线性段落**：把八段文字摊成一座岛的地图 —— 码头、仓库、小路、集市、
   灯塔区。数据不再按段落排列，而是**长在它所属的物件上**（背包在码头、价签在集市）。
2. **关联 = 连线**：实线 = 数据依赖（包裹「恰好是第一行」），虚线 = 计入密码。
   点亮一个节点，就是「处理掉了这条关联」。
3. **渐进披露**：点开物件才看到细节数据与算式；第一眼只有场景与物件名 ——
   压力分层，而不是一次糊 800 字。
4. **混合知识点标签**：每个物件的卡片列出它承载的 3~5 个知识点标签（chip），
   体现「一句话/一个物件 = 交叉的几个知识点」。
5. **一道题的仪式感收束**：八个账面数最终汇入灯塔，输入密码点亮 ——
   可视化的终点和文字题完全一致（答案仍是 1424）。
6. **诊断也可视化**：密码输错 → 可打开「对照层」逐个核对八个账面数，
   第一个对不上的就是断裂的关联（与方案二同一套诊断逻辑）。

## 四、呈现形态光谱（本方案的位置与后续演进）

| 档位 | 形态 | 说明 |
|---|---|---|
| ① 静态信息图 | 一张关联大图 | 最轻，不可交互 |
| **② 交互场景图 ← 本 H5** | 场景 + 点击物件 + 连线 + 揭示 | 看得见、点得动，仍是同一道题 |
| ③ 轻动画 | 关联线上流动光点、灯塔扫光 | 强化「链在动」的感觉 |
| ④ 小游戏 | 拖拽物件配对关联 / 拖数字进灯塔 | 把「处理关联」变成玩法 |

本交付实现的是 **② 交互场景图**，为 ③④ 留好了结构（节点、连线、揭示状态都是数据驱动）。

## 五、H5 原型说明（同目录 index.html）

**文件**：`index.html` + `style.css` + `app.js`（零依赖，直接浏览器打开或起本地服务）。

**结构**：

```
┌────────────────────────────────────────────────────┐
│ 顶栏：标题 · 关联显示开关 · 账面数进度 x/8 · 对照层   │
├──────────────────────────────────┬─────────────────┤
│ 场景图（SVG 夜岛）                 │  物件卡片（右栏）  │
│  码头(背包/绳板/钱包/交接单)        │  · 场景数据       │
│  仓库(罐头) 小路(地砖)            │  · 要处理的关联    │
│  ●账本第一行 ← 6 条依赖线          │  · 知识点 3~5 个   │
│  包裹 → 集市秤 → 灯罩（链）         │  · [处理这条关联]   │
│  地基·砖堆·灯室·圆底座             │    → 揭示账面数    │
│  🗼灯塔（唯一输入框：密码）          │                 │
└──────────────────────────────────┴─────────────────┘
```

**玩法**：

1. 点任意物件 → 右栏出现它的卡片：**场景数据 + 要处理的关联 + 混合知识点标签**；
2. 点「处理这条关联」→ 揭示这个数（算式一并给出），节点点亮；
3. 有依赖的节点必须**先处理上游**（账本要先点亮它的 6 个来源）—— 用交互复现依赖链；
4. 顶栏「关联」开关 → 显示/隐藏全局连线（实线依赖、虚线计入密码）；
5. 八个账面数集齐 → 点灯塔输入密码 **1424** → 点亮动画；输错可开「对照层」核对。

**预览**：

```bash
cd 学习方案 && python3 -m http.server 8643 --bind 127.0.0.1
# 打开 http://127.0.0.1:8643/
```

所以方案三的 H5 入口放在本文件夹内，见 `设计框架/00-目录地图.md`。）
