# 交互契约（第 1 层：用户按下什么，**应该**发生什么）

> **本文件按"层"组织**（用户 2026-09-28 的要求：「你应该先去说在哪一层？是实时交互层还是
> agent 的执行层」）。同一件事在两层里的行为**不一样**，所以先分层再写行为。
>
> 证据标记：`【实测】` 真机量过；`【代码】` 读代码确认；`【你说】` 你口述的（已落字）；
> `【可能矛盾】` = **你这次说的与代码/实测不一致，我没改表，等你定**；`【待你确认】` = 空着等你说。

> 最后更新：2026-09-28（第二轮：按层重写 + 收进你的口述）。

## 0. 两层是什么（先用你的话定下来）

| 层 | 怎么进 | 干什么 |
|---|---|---|
| **实时层** | **第一次按下**快捷键 | **梳理你的需求**：右上角看板记录你说过的每一件事（脑图分类），并**专门找逻辑矛盾**；右下角卡片回答你**最新的那个问题**。**不执行任务** |
| **执行层** | **再按一下**（= 提交） | 把这一层前面攒下的东西（你的话 + 参考材料 + 你确认过的方向）交给 agent **真的去做** |

`【你说】` 实时层有**两种用法**，两种都算实时的目的：
1. **临时问一句**（问完就走，不交给 agent）；
2. **梳理需求**：一边说一边看右上角——"我的需求是不是梳理清楚了？矛盾点是不是有我没讲清楚的地方？"
   确认都清楚了，**再按一下交给 agent 去做**。

⚠️ **没有"点两下"这个手势** `【你说】`：两层都是**按一下就进入**。
`【可能矛盾】` 设置页里那个选项现在叫「按住说话 / 点两下说话」，当前用的是后者 ——
**名字和你的模型对不上**（"点两下"听起来是双击手势 ✗，而你要的是"每次按下都是一次动作"✓）。
代码里的"点两下"确实是"第一下开始、第二下发送、忽略松手"，与你要的**行为一致** ✓，
只是**标签名会误导人** ✗。要不要改标签，你定。

⚠️ **实时层里按快捷键到底算不算"提交"** `【可能矛盾】`：
你说「在实时层…**没有快捷键这种逻辑**（只能等静音自动提交）；在 agent 层里才既能等、也能按」✗；
但"按一下进入执行层"这一下**本身就是按快捷键** ✓。我暂时按**下面的表**写（= 代码现状），
并在这一行留着这个疑问 ✗ —— 你确认一下我理解得对不对。

## 1. 实时层

### 1.1 开始

| 项 | 行为 |
|---|---|
| 第一次按下 | 进入实时层，开始听 `【你说】` |
| 触发方式 | **按一下**（不是按住、也不是双击）`【你说】` |

### 1.2 提交（离开实时层）

| # | 情形 | 应该发生什么 |
|---|---|---|
| 1 | 说完话，**安静到设定时长** | **自动提交**（你设的是 **1 秒**；默认 1.5 秒）`【实测】` |
| 2 | 说完话，**再按一下快捷键** | **提交** `【实测】` |
| 3 | AI 还在说 / 说完了但你**没说话**，按一下 | **结束本次对话**（= ESC 的效果）`【实测】` |
| 4 | 追问窗口已经关了（30 秒过完） | 开**新的一大轮** `【代码】` |

`【你说】` **空转写不发** —— 没必要发，发了也没意义 ✓（现状如此 ✓）。

`【你说】` **"半秒内按"那件事不用管**：你不会那样按（说完会等一小会再按）；
按代码现状走即可 ✓ —— **这条从"待确认"里撤掉了** ✓。

### 1.3 实时层里那两张卡片的分工

| | 右上角（看板） | 右下角（回复卡） |
|---|---|---|
| 管什么 | **梳理你的需求**：你问过的**每一件事**（相关的不相关的都记），脑图**分类**整理 | 回答你**最新的那个问题** |
| 特别要做的 | **专门找"逻辑矛盾"**（你自己话里前后不一致的地方）—— `【你说】` **这是重点** | 判断**最新的问题与之前有没有关系** |
| 有关系时 | 继续往同一张图上长 | 当作**追问**处理（参考之前的内容） |
| **没关系时** | —— | **完全忽略之前的上下文**，只回答最新这一个问题 `【你说】` |

`【你说】` 追问的例子：「北京在哪里？」→「什么在哪里？」→「你确定吗？」——
后面这两句字很少，但都是**在追问**，所以**要参考之前的内容** ✓。

### 1.4 什么时候离开实时层

- 提交（见 1.2）→ 进执行层；
- 按 ESC → 结束这一大轮（见 §3）；
- 再按一下但没说话 → 结束（同 1.2 第 3 条）。

## 2. 执行层（agent 模式）

| 项 | 行为 |
|---|---|
| 进去之后 | 把你说的话 + 参考材料 + 你确认过的方向**交给 agent 去做** |
| 看板 | **一律不显示**，而且那条链**一个字都不跑**（不轮询、不问模型）`【实测】` |
| 结果去哪 | **右下角那张卡片**（鼠标旁）+ 播报 |
| 继续追问 | 在追问窗口里说话（打断）→ 同一条链：开口即打断，说完按快捷键或等静音 = 提交 |
| 结束 | 按 ESC / 再按一下快捷键 / 窗口到期（30 秒没人说话） |

## 3. ESC（两层通用）

| 顺序 | 此刻 | ESC 应该做什么 |
|---|---|---|
| 1 | 转写编辑窗开着 | **收起编辑窗**（不打断这一轮） |
| 2 | 正在录音 | 中断录音，**录音照存**，这一轮**什么都不发** |
| 3 | 正在跑（思考/播报/agent） | 真打断：停播报、收掉鼠标旁那张卡片、收掉**这一次提交**派出去的 agent |
| 4 | 上面都不成立、但追问窗口开着 | **关掉那个窗口**（= 结束本次对话）`【实测】` |
| 5 | 什么都没有 | 什么都不做，ESC 原样进前台 App |

### 3.1 手动退出 = 结束（你的原话）

> 「我手动退出了，那相当于是我代表这个任务已经完成了呀？他还是在监听我，那相当于是永远无法停止。」

`【实测】` **再按一次快捷键**和**按 ESC** 两条路都必须把追问窗口关掉，
而且**关掉之后不许自己回来** ✓（`scripts/listening-stop-check.sh` 四个断言 × 两条路 × 三轮全绿）。
`【你说】` **所有历史记录全部清零，代码停止** ✓ —— 现状如此 ✓。

### 3.2 打断的范围 = **一个"周期"**

> 从**第一次按下**到**最后一轮 AI 回复结束**，中间出现的**所有 agent** 都终止；
> 对**其他轮**、对**全新的一轮**没有任何影响。

`【代码】` 判据是 `cycleID`（不是会话、不是时间戳、不是卡片）。

`【你说】` **"Claude Code 卡片只有一个子进程、只停这一轮做不到"这句你没看懂** ——
用大白话再说一遍：**那张卡片从头到尾只有一个后台进程** ✓，所以"停掉这一轮"只能连它**更早那一轮**
的活一起停 ✗ —— 这是数据结构本身的限制（要改就得让一张卡能同时开多个进程 ✗）。

## 4. 追问窗口（播完之后还能继续说）

| 项 | 值 |
|---|---|
| 什么时候开 | 回答**开始播放**时开（那是打断的耳朵） |
| 30 秒从哪算 | **回答念完那一刻重新起算** `【实测】` |
| 多长 | 设置 → 听 → 监听时长（当前 **30 秒**；0 = 播完就关麦） |
| 窗口里再说话 | 与"打断"走**同一条链** |
| 关掉意味着 | 这一大轮结束：看板与上下文**全部清空**，下一次按下从零开始 |
