## 7. 版本方案：**自建增量快照**（2026-09-30 定，回答你那个问题）

你问的：「如果用户在另外一个项目里面对软件进行修改，这个 Git 会不会受到影响？」

**先答这个问题（事实）**：
- 我们恢复的只可能是**这个项目文件夹里自己那份文件**，操作是「按文件取出某一版」，
  **不会去改任何别的文件、更不会碰你在别的项目里的仓库**。
- 但**真 git 有一个副作用**：它要在你那个项目文件夹里放一个 `.git/` 目录。
  · 如果那个文件夹本身**不在**任何 git 仓库里 → 只是多了个隐藏目录，别处不受影响；
  · 如果它**已经在**另一个仓库里（比如你在某个仓库里又建了子项目）→ 会多出一个
    **嵌套仓库**，外层 `git status` 会看见一个没跟踪的条目（不 `git add` 它就只是多个条目，
    不会改你任何代码，但会让外层仓库"看起来多了个东西"）。

**结论（我按你授权选的方案）**：**自建增量快照，不碰你项目里的任何 git**。
理由三条，都对着你的目的（**单文件的编辑历史与恢复**）：

1. 目的就是"改了某个文件，想回到某一版" —— 按文件存版本，**天然就是单文件恢复**；
2. 不往你目录里放 `.git`，也就没有"外层仓库多一个条目"这件事，**零副作用**；
3. 不依赖 git 是否安装、不用解释"为什么我的项目里多了个 .git"。

真 git 不是不做，是**不做默认**：要的话做成一个开关（「这份历史用 git 记」），
需要时再开 —— 但按极简原则，**第一版不做**，等你真的需要再说。

`89f3a39` 加的「点外面就关菜单」用的是 **`mousedown` + capture**：

```js
document.addEventListener('mousedown', () => {
  document.querySelectorAll('.menu').forEach(m => { m.hidden = true; });
}, true);
```

capture 阶段**先于**菜单项收到 mousedown，于是菜单在你手指还没抬起来时就 `display:none` 了
→ mouseup 落到 body → `click` 的共同祖先是 body → **菜单项的 `onclick` 一次都不会执行**。

实测（Playwright，打开「设置」菜单点第一项「对话在左」）：

| 读数 | 期望 | 实际 |
|---|---|---|
| 菜单点完是否关闭 | 关 | **关** ✓（所以看起来"生效了"） |
| 顶栏按钮文案 | `对话·左` | **`对话·右`** ✗ |
| `#main` 的 class | 含 `left-layout` | **`main`** ✗ |

**也就是说 §13.2 / §14.6 / §15.6 / §16.5 / §17.1 建起来的那整套右键菜单与下拉菜单，
点下去全都不执行**，只有"菜单会自己关掉"这一半是真的。你只在「固定标签页」上发现了它，
是因为只有那一处你明确知道点了该发生什么。

| # | 判据 |
|---|---|
| 20.0.1 | 关掉 `mousedown` 那条 capture 钩子 —— 「点外面必须关」由**已有的 document `click` 钩子**承担（它跑在气泡阶段，菜单项的 `onclick` 先执行） |
| 20.0.2 | 每个菜单**自己在动作里收场**（`closeMenus()` / `hidden = true`），实测：点一项 → 动作真的执行 **且** 菜单关掉 |

不在 `.menu` 里，它按下的那一刻仍然会把菜单关掉，而它自己的 `onclick` 是 `hidden = !hidden`
