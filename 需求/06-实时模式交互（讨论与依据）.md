## 0. 一句话

**一个大循环，两个模式：先进实时模式（快、不出声、临时会话），按一下进 Agent 模式（慢、出声、正式会话）。
说话 = 打断或追问；按快捷键 = 开始 / 提交 / 终止。**

---

## 1. 先把词定死

| 词 | 含义 |
|---|---|
| **大循环**（一次任务） | 从**第一次按下快捷键**开始，到 ESC 或"Agent 模式下再按一次快捷键"结束 |
| **实时模式** | 大循环的前半段。**非思考模型** + **临时会话**。回答只上右下角卡片，**不出声** |
| **Agent 模式** | 大循环的后半段。**思考模型** + **正式会话（连续对话）**。回答**显示 + 出声** |
| **临时会话** | 实时模式专用的会话。**进 Agent 模式即作废**（内容已移交） |
| **说话** | 用户开口（麦克风检测到人声） |
| **打断** | **AI 正在播放声音时**用户说话 |
| **追问** | **AI 播放完成之后**用户说话 |
| **提交** | 按下快捷键，把**用户刚说的那句话**发出去 |
| **终止** | 按下快捷键 / ESC，**结束整个大循环** |
| **监听窗口** | 麦克风继续开着的那段时间 —— **大循环结束后 60 秒**（§8） |

## 2. ⭐ 大循环，以及**模式不会自己退出**

```
        【开始】第一次按下快捷键
              │
              ▼
    ┌─────────────────────────┐
    │  实时模式（临时会话）     │  说话 → 静音 1 秒自动发 → 卡片（不出声）
    │  追问也在这里循环         │  再说话 → 还是临时会话 → 卡片
    └───────────┬─────────────┘
                │ 按下快捷键 = 强制进 Agent（**没有前提**）
                │ 移交：全部历史 + 最后一问
                ▼
    ┌─────────────────────────┐
    │  Agent 模式（正式会话）   │  回答 = 显示 + 出声
    │  追问也在这里循环         │  打断 / 追问 → 都还在 Agent 模式
    └───────────┬─────────────┘
                │
      ┌─────────┴─────────┐
      ▼                   ▼
  【结束】ESC        【结束】再按一次快捷键
```

### 2.1 ⭐⭐ 模式**不会自动退出**（这一条是这一轮新加的，最要紧）

`【你说的】` 逐字：

> 「进入 agent 模式下，**只要用户没有按下 ESC，或者没有第二次按下这个快捷键，
> 那么就永远处在 agent 模式下。即便电脑关机 24 小时，它都是在 agent 模式下，不会自动触发关停**。
> 实时模式也是一样的，只要用户按下第一次快捷键，进入实时模式，那么只要用户没有第二次按下这个快捷键，
> 它就永远在实时模式，**无论电脑运行多长时间，永远在这个模式**。**它的切换主要是按照快捷键来切换的**。」

落成三条：

| # | 规矩 |
|---|---|
| 1 | **模式靠快捷键切换，不靠时间**。没有任何"等 N 秒自动回到上一个模式"这回事 |
| 2 | **实时模式**：从第一次按下起一直有效，直到你第二次按下（进 Agent）或按 ESC（结束） |
| 3 | **Agent 模式**：从第二次按下起一直有效，直到你按 ESC 或再按一次快捷键（结束）。**关机、重启、隔天回来，都还在 Agent 模式** |

> ⚠️ **它和"监听窗口"是两件事，别混**：模式是"我现在在哪个模式"（**永久，直到你按快捷键**）；
> 监听窗口是"麦克风还开着多久"（**循环期间一直开着；循环结束后再热 60 秒**，见 §8）。

## 3. ⭐ 按下快捷键 = 什么？（**按"轮到谁"分**）

`【你说的】`（2026-09-30 更正，逐字）：

> 「**ESC 是强制性退出，无论处于任何一个状态。而快捷键是分场景的：AI 正在说，或者 AI 说完，
> 快捷键就是结束；用户正在说，或者用户说完，快捷键等于发送。**」

所以判据只有一条：**此刻轮到谁**。

| 此刻轮到谁 | 按下快捷键 = |
|---|---|
| **用户**（正在说 / 刚说完） | **发送**（把这句话发出去） |
| **AI**（正在说 / 刚说完） | **结束**（终止大循环） |
| **都不在**（不在大循环里，空闲） | **开始新的大循环** → 实时模式 |

**落到两个模式上**：

| 模式 | 按下 = | 为什么 |
|---|---|---|
| **实时模式** | **发送 → 强制进 Agent 模式**（**没有前提**） | 实时模式**不出声**，所以"AI 正在说"这个状态**不存在** —— 永远是"轮到用户"，于是按下永远是"发送"，而实时模式里的"发送"就是提交给 Agent |
| **Agent 模式** | 用户轮到 → **发送**（仍在 Agent 模式）<br>AI 轮到 → **结束** | 出声，所以两种状态都存在 |

`【你说的】` 补充：Agent 模式下用户说完话，**不按也行 —— 静音 1 秒自动提交**，
提交之后**还是在 Agent 模式**（「因为这个时候用户既可以追问，也可以提供其他问题」）。

### 3.1 ⭐ ESC —— 和快捷键相反，**不分场景**

`【你说的】`：「**ESC 是强制性退出，无论处于任何一个状态。**」

| 状态 | 按 ESC |
|---|---|
| 用户正在说话 | **退出** |
| 用户说完话 | **退出** |
| AI 正在说话 | **退出** |
| AI 说完话 | **退出** |

（实时模式里同理：ESC = 取消发送 + 取消右下角卡片 + 结束这一轮。）

**一句话对照**：**ESC = 无条件退出；快捷键 = 看轮到谁**（用户 → 发送，AI → 结束）。

## 4. ⭐ 说话 = 什么？（打断 / 追问）

**说话本身永远不结束大循环**，只分两种（`【你说的】`「打断和追问在实时模式和执行模式中都存在」）：

| 什么时候说话 | 叫 | 会发生什么 |
|---|---|---|
| **AI 正在播放声音** | **打断** | ① 立刻停掉正在播的声音 ② **右下角卡片瞬间消失** ③ 麦克风继续收这句话 |
| **AI 播放完成之后** | **追问** | **右下角卡片瞬间消失**，麦克风继续收这句话 |

> `【你说的】`「用户说话时右下角卡片消失，这是正确的，因为**用户说话就是一个全新的问题**。
> 右下角卡片显示的是 AI 回复的结果……只有用户看完这个答案时，他才会去提问。」

**打断只在 Agent 模式听得出来**（实时模式不出声，没有"正在播放"这个状态）——
所以实时模式里只有"追问"这一种。`【我补的·请核对】`

## 5. 实时模式（大循环的前半段）

| 项 | 行为 |
|---|---|
| 模型 | **非思考模型**（设置 → Agent →「Pi 模型」里"实时"那一行） |
| 会话 | **临时会话** |
| 说完话 | **静音 1 秒自动发送** |
| 回答去哪 | **只有鼠标右下角卡片**（流式） |
| 出声吗 | **不出声** |
| 追问 | 用户再说话 → **还在这个临时会话里**继续（「实时模式的追问在临时会话里继续」） |
| 追问的节奏 | 同样**静音 1 秒自动发送**，循环 |
| 按 ESC | **取消发送**（这句不发）+ **取消右下角卡片** |
| 按下快捷键 | **强制进 Agent 模式**（§3、§6） |
| 什么时候离开 | **只有**按下快捷键或 ESC。**没有自动退出**（§2.1） |

## 6. ⭐⭐ 进 Agent 模式那一刻（**移交**）

### 6.1 移交给什么

`【你说的】` 逐字：「会把**刚才的问题**以及**实时模式下的全部历史、所有聊天记录**都发到执行模式里。
**第一件事是把所有历史发进去，备注为参考信息或聊天记录；最后补一行，备注用户最近一次的问题是什么，
让它重点关注**。」

**为什么要全部历史**（`【你说的】`，这条要记住）：
> 「因为用户在追问，他可能有**三轮、四轮、五轮、七轮、八轮、九轮、十轮**，
> 所有这些东西未来对用户来说都可能非常重要，**他可能需要整理或保存完整记录**，所以不能只保存一部分内容。」

⚠️ **而且要注意上下文压缩**（`【你说的】`）：
> 「因为实时模式跟临时模式……它们都有会话记录，也有上下文管理，**也有上下文压缩**，
> 所以你必须注意到，**你要提供给 AI 的是完整的历史**。**如果上下文过爆或者曾经触发过上下文压缩，
> 那么你就要把这个文件发给 AI**，让他知道，**让他能够看到全部的历史**。」

也就是说：**不能拿"压缩过的摘要"去移交** —— 移交的必须是**完整原文**。

### 6.2 用什么格式写（XML 标签）

`【你说的】`：「用标签的形式来写……用 **XML** 这种标记语言来标记这些内容。
把之前的所有内容当作历史，**最后一句用另一个独立的标签来标记**，
这是你要让 AI 完成或重点关注的任务，**把它当作终极目标来执行**。」

**⭐⭐ 标签的名字叫 `goal`（2026-09-30 你纠正的）**

你逐字：
> 「**它就是 goal，G O A L。**……**没有 cloud task，这个 goal 它本身就是标签。**
> 你说的这个书签、这个特殊符号，**它本身就是标签**，不是外层标签。……
> **你要写的是标签的名字，标签的名字叫 goal。**」

⚠️ **我上一版写错在哪**：我把它写成了两层 —— 外面套 `<cloud_task>`、里面再放 `<goal>`。**错的。**

**查过了**（`全局框架/官方依据.md` P29，来源 MDN）：*"a **tag** is used for creating an element"*，
而 *"the **name** of an element is the name that appears at the beginning of the element's **start tag**
and at the end of the element's **end tag**"* —— 也就是：
**`<goal>…</goal>` 这一对本身就是"标签"，`goal` 是"标签的名字"。外面不需要再包一层。**

**正确的写法**（两个标签，各自独立，谁也不包谁）：

```xml
<history>
（实时模式下的全部对话，按时间顺序，一轮一条）
[用户] ……（他说的话）
[助手] ……（实时模式回的）
[用户] ……
[助手] ……
…
</history>

<goal>（用户最后问的那一句 —— 只有问题，没有回答）</goal>
```

> `【顺口确认】` 第一个标签的名字我用的是 **`history`**（因为你说"把之前的所有内容当作历史"）。
> 要换成别的词，说一声。

**最后那个标签的作用**（`【你说的】`）：
> 「用户最后说的这句话**很有可能是一个执行的指令**，所以你要去告诉 AI，
> **请你以最后一句话为标准，来完成用户的要求或任务**。」

**举的例子**（`【你说的】`）：
> 「用户可能连续追问 10 轮，学到了一些知识，最后一句说**把这些东西整理到笔记里**，
> 那么"整理到笔记里"其实是个**指令**。虽然对 AI 来说它是历史对话，但你把它**单独提出来**，
> 这也是用户的一个简要表达，能让 AI 理解整个交互逻辑，**相当于更符合人类的交互逻辑**。」

### 6.4 ⭐ 两个标签的分工（**已确认，2026-09-30**）

你逐字确认的：

> 「**之前所有的卡片，包括最后一句和最后一句的回复，全部当作历史，这是正确的。**
> 但我说的是**第一个标签**，你能理解吗？你发给执行模式的时候有两个标签：**第一个标签就是刚才说的这个；
> 第二个标签是用户的最后一条，只有这个问题，没有这个问题的结果**。我的意思是，**只把这个问题写上，
> 因为 AI 一定会回复用户结果。所以你把最后这一轮的问题提取出来就可以了**」

| 标签 | 里面放什么 |
|---|---|
| **第一个（`<history>`）** | **全部历史 —— 包括最后那一问、以及它的回复**。一条不少 |
| **第二个（`<goal>`）** | **只有用户最后那一句问题**，**不带它的回复** |

**为什么第二个里不要回复**：`【你说的】`「**因为 AI 一定会回复用户结果**」——
那个块是"要它去做的事"，不是"已经做过的事"。把回复塞进去，它就可能以为已经做完了。

**完整例子**（你那个"连续追问 10 轮"的场景）：

```xml
<history>
[用户] 帮我看看这篇文章
[助手] 这篇文章讲的是……
[用户] 再短一点
[助手] 讲的是……
[用户] 把这些整理到笔记里
[助手] 好的，整理成这样的三条……（← **保留，它属于历史**）
</history>

<goal>把这些整理到笔记里</goal>
```

> 也就是说：**"最后一条回复"在历史里留着**（你之前那句「全部当作历史」是对的），
> 它只是**不出现在第二个标签里**。我之前把"删掉"读成了"从历史里删掉" ✗ —— 已改正。
>
> ⚠️ 两个标签**各自独立、谁也不包谁**（§6.2 那条纠正）。

## 8. ⭐⭐ 麦克风 / 引擎开多久（**2026-09-30 更正：是 60 秒，而且从"大循环结束"起算**）

### 8.1 为什么要热着（你讲的道理，先记住）

`【你说的】`：
> 「**引擎开启的目的是让它能够识别用户的声音，方便打断 AI 的内容，能够识别打断，
> 这就是引擎热着的意义。**」

### 8.2 ⭐ 开多久（更正后的规矩）

`【你说的】` 逐字：

> 「**引擎开始的时间要写上：从用户按下快捷键进入实时模式的时候，这个时间就已经开始了，
> 然后持续到整个大循环结束，再加上 60 秒。** 也就是说，整个大循环结束后，用户说什么话
> 都不会被录到，所以基本上已经没有什么意义了。**之所以还要加上 60 秒，是为了防止用户第二次
> 发起循环时引擎还冷着。如果持续让它热 60 秒，第二次发起循环就可以直接快速进入实时转录模式，
> 或者叫实时打断模式，不需要再等引擎启动的时间。**
>
> 所以这个 30 秒窗口其实是在**结束大循环的那一秒**开始计时，**不是 30 秒，是 60 秒**。
> 我刚才说错了，文档里面那个数字，把它调整为 **60 秒**。」

| # | 规矩 |
|---|---|
| 1 | **麦克风从"按下快捷键进实时模式"那一刻就开着** |
| 2 | **整个大循环期间一直开着** —— 不用一轮一轮重新计时（会话在继续，它就在听） |
| 3 | **大循环结束后，再热 60 秒**（这 60 秒里说话**不会被处理**，纯粹是让引擎别凉） |
| 4 | 那 60 秒的**唯一目的**：你**第二次发起循环**时，引擎是热的 → **立刻**能听、能打断，不用等启动 |
| 5 | 数字是 **60 秒**（不是 30 秒）—— 对应设置里的「监听时长」，**默认值要改成 60** |

> ⚠️ **这条更正取代了我上一轮记的"每轮续 30 秒"**：按这次的说法，**循环进行中根本不用算窗口**
> —— 麦克风就是一直开着；需要计时的那一段**只在循环结束之后**（60 秒）。
>
> `【请你顺口确认一下】` 如果**循环进行中**确实还有"安静太久就停"的意思（也就是那个"续 30 秒"），
> 告诉我一声，我把它加回来 —— 按这次的说法，它是没有的。

## 9. 声音引擎（3 分钟）

`【你说的】`：「**声音引擎，必须继续停留 3 分钟**，目的就是更快的发出声音等等」。
