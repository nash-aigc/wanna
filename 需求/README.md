# 需求/

**这个目录回答"这个软件应该是什么样"，`开发经验/` 回答"我们踩过什么坑"。**

两者的分工不能混：
- `开发经验/` 是**事后**的（某个问题怎么修的、量到什么数字）；
- `需求/` 是**事前**的（用户要什么、屏幕上该显示什么、按下什么该发生什么）。

**为什么要分开**：过去所有东西都只能从 `开发经验/` 里反推"应该是什么样" ✗ ——
而那份东西是**按问题编号**组织的（D39、9.55……），它回答不了"整体应该是什么" ✗。
后果是**代码逻辑变成事实上的需求**：AI 改一处代码、测试按代码的逻辑判绿 ✗，
而用户真正要的那件事可能已经被改掉了 ✗。
