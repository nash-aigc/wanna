# 00 · 目录地图 —— 这个项目怎么整理

> **这一份回答三个问题**：每个文件夹是什么、能不能进 git、动它会不会弄坏东西。
> 新增文件夹、挪文件、`git add -A` 之前**先看这张表** —— 这个项目已经吃过
> 「临时文件散在根目录、后来找不到哪个该留」的亏。
>
> 维护规矩：**加了新目录就在下表加一行**，改了引用关系就同步改「谁在引用」那一栏。

## 二、这个项目的规矩（新增东西照这个来）

| 东西 | 放哪 | 入库 |
|---|---|---|
| 用户要什么 | `需求/NN-*.md` | ✅ |
| 系统现在什么样 | `全局框架/NN-*.md` | ✅ |
| 踩过的坑 / 实测数字 | `开发经验/NN-*.md` | ✅ |
| 怎么整理 / 怎么设计 | `设计框架/` | ✅ |
| 给用户拍板的样式稿 | `设计稿/` | ✅ |
| 调效果用的过程页 | `design-preview/` | ❌ |
| 运行时产生的数据 | `Wanna录音/` 等（见 C 节，别乱挪） | ❌ |
| 第三方源码克隆 / 官方文档副本 | **`reference/`**（只剩这一个，别再拆出第二个） | ⚠️ 除 `pi` 已入库，其余 ❌ |
| **临时文件、截图、中间产物** | **`.cache/`** | ❌ |
| 探针 / 自检脚本 | `scripts/` | ✅ |
| **原型用的媒体资源**（音频/图片） | **`sfx/`**（如 `sfx/pulse-*.wav`，来自 MiMo-Code，MIT） | ✅ |

**三条硬规矩**：

1. **根目录不放散装文件**。新东西先问「它属于上表哪一行」，不属于就先想清楚职责再建目录。
2. **`git add -A` 之前先看 `git status`**。这个仓库的 `.gitignore` 挡了 12 类东西，
   但**挡不住已经入库的**（第四节就是活例子）。
3. **移动任何目录之前，先搜代码里的引用**：
   `grep -rn "目录名" --include="*.swift" --include="*.js" --include="*.md"` ——
   注释里的引用也算，因为那是「按图索骥」的线。

## 四、一个必须记住的坑：`gitignore` 挡不住已经入库的东西

```
.gitignore:77:reference/     ← 写了
git ls-files reference       ← 1967 个文件照样在版本控制里
```

`.gitignore` **只对「还没被跟踪」的文件生效**。文件在加进 git **之前**就进去了，
之后再补规则**一点用都没有**——它只会安静地继续被跟踪，`git status` 也不会提示你。

所以判断「这个目录到底入没入库」，只能用：

```bash
git ls-files 目录名 | wc -l     # 非 0 = 已经在版本控制里了
```

`开发经验/运行日志/`（287 个）和 `reference/`（1967 个）就是这么变成「以为挡住了、
其实在仓库里」的。**新加 ignore 规则后，顺手跑一次上面这条命令核对。**
