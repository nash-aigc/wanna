# 原型 UI 风格规范（强制 · §50 起每批机器级遵守）

> **这份文件是原型所有按钮/颜色/菜单的唯一真相。** 用户 2026-10-03 原话：
> 「没有的话提取成文件，然后写入 claude.md」「我不希望再看到（UI风格不统一）」「不希望看到任何的按钮的弹窗 or 菜单位置错误」。
> **改任何原型 UI 之前先读这里**；与本文件冲突的写法一律改到合规为止。
> 出处与教训：D80（三种色并存、主按钮挂错变量）、§35.11（菜单曾盖住触发它的按钮，用户点名两次）。

## 一、颜色 tokens（只许用这些，不许现写十六进制）

| token | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--accent` | `#0A84FF` | **主操作色**：primary 按钮底、选中态边框/底色、开关打开态、输入聚焦 | 不用于文字正文 |
| `--grad` | `linear-gradient(135deg,#0A84FF,#7A5CFF)` | **主 CTA 渐变**（`.hbtn.primary`、`.btn-primary`） | 不用于小图标/描边 |
| `--focus` | `#F5B851`（琥珀） | **只**用于：hover 边框环、输入 focus 环、焦点类小图标（星标/路径） | ⛔ 不许当按钮底色（D80 根因） |
| `--ok` / `#4ADE80` | 成功、在线徽标 | 不用于按钮底 |
| `--warn` / `#FBBF24` | 待回顾、警示徽标 | 不用于按钮底 |
| `--red` / `#FF6B6B` | danger 按钮、删除、失败 | 只配 danger 家族 |
| 层级 | `--bg` 页底 / `--surface` 顶条 / `--surface2` 卡底 / `--line` 描边 | 背景只从这四个取 |
| 文字 | `--ink` 主 / `--ink2` 次 / `--ink3` 弱 | — |

**一屏只许出现两套色语义**：accent 蓝 = 操作/选中，focus 琥珀 = 悬停/焦点。**不许出现第三种蓝**（历史上的 `#3B82F6` 已全部清除，禁止回潮）。

## 二、按钮（`.hbtn` 家族 —— 唯一按钮体系）

所有按钮**必须**是 `.hbtn` 变体，不许裸 `<button>` 配颜色、不许 inline `style="padding…"`。

| 类型 | 规格 |
|---|---|
| `.hbtn` 基础 | min-height **32px** · padding 7px 16px · 13px/500 · radius 9px · bg `--surface2` · border 1px `--line`；hover：border `rgba(10,132,255,.55)` + bg `#232830` |
| `.hbtn.primary` | `--grad` 渐变底 · 白字 600 · 无边 · hover `brightness(1.1)` + 轻投影；**一页最多一个 primary**（当前步骤的主动作） |
| `.hbtn.ghost` | 透明底无边 · color `--ink2` · hover bg `rgba(255,255,255,.07)`；用于次要动作（查看/说明类） |
| `.hbtn.danger` | bg `rgba(255,107,107,.16)` · border `rgba(255,107,107,.45)` · color `#FF9B9B`；**只给删除/中断/销毁** |
| `.hbtn.sm` | min-height **26px** · padding 3px 10px · 12px —— **唯一允许的小号**，用于卡片内密集操作（重来/×/describe）。**不再允许 inline padding** |
| `[disabled]` | opacity .45 · cursor default |

**硬规则**：
1. 主动作 → `primary`；次动作 → 基础；说明/查看 → `ghost`；销毁 → `danger`。
2. 同一操作区按钮**同高**（全尺寸互相同高；`.sm` 互相同高，不许混）。
3. 写按钮前先搜有没有现成 `.hbtn` —— 有就用，不许新造样式。

## 三、开关 / 设置行 / 下拉（复用件，不许重画）

- **开关**：`.hsw`（iOS 形 40×22，打开 = accent）。**不许**裸 checkbox 当开关（D80 记忆页教训）。
- **设置行**：`.hset`（左 `.tx` 标题+描述 / 右 `.ct` 控件，行间 1px 分隔）——所有"一行一个设置"的排版都用它。
- **下拉**：一律原生 `<select>` + 统一 CSS（`appearance:none` + 自绘箭头 + `#101418` 底，见 §47 块）。**不许**自造下拉面板，除非 `showMenu`。
- **模式选择卡**：`.hmode-card`（选中 accent 边 + ✓）。
- **表单输入**：`.hform label` 内的 input/textarea，或 `.hrow` 裸 input（CSS 已给同款底色）。

## 四、菜单与弹层定位（「不许盖住触发按钮」）

| 浮层 | 定位规则 | 代码 |
|---|---|---|
| 带锚点的下拉菜单 | **贴锚点上方**（底边 = 锚点顶边 − 6）；上方放不下自动**翻到下方**（起点 = 锚点底边 + 6，翻下也不压按钮） | `showMenu(items, anchor)` → `placeMenuAbove(m, r.left, r.top, r.bottom)` —— 只许走 showMenu |
| 手动下方菜单 | 锚点**下方** +6；放不下夹进视口 | `placeMenu(m, r.left, r.bottom + 6)` |
| 子菜单/级联 | 父项**右侧** +6，垂直对齐父项顶 | `placeMenu(m, r.right + 6, r.top)` |
| 右键 | 光标处（xy 分支） | `showMenu(items, null, {x,y})` |
| 模态（askModal/confirm） | 居中 + 遮罩（这是模态的本义，不算"盖按钮"） | `openModal` |

**验收断言（每批样式判据必带，Playwright）**：打开任一锚点菜单后，
`menuRect ∩ anchorRect === ∅`（菜单矩形与触发它的元素矩形**不相交**）。
新增菜单**只许**调 `showMenu` / `placeMenuAbove` / 上表的下方公式 —— 不许自己算 `style.top`。

## 五、每批必带的两条样式断言（写进判据表）

1. **按钮**：任取页内 `.hbtn`（非 .sm）→ `getComputedStyle().minHeight/实高 ≥ 30px`，primary 背景 ∈ {渐变, accent 蓝}。
2. **菜单**：打开一个锚点菜单 → 菜单与锚点矩形不相交；点外面关闭。

## 六、功能完整性自问清单（用户：「你自己应该独立考虑」）

每批收工前逐页过一遍，缺了就补、不许留给用户发现：
- 列表页有没有**添加/新建**入口？（光有表单没有按钮、或光有列表没有入口都算缺）
- 提示"有问题"的地方有没有**修复入口**？（linter 报缺 description → 必须能编辑）
- 打了标（handoff/归档/归档技能）有没有**撤销**？
- 有增删的有没有**改**？（cron 能删不能改 = 不完整）
- mock 的地方有没有**如实标注** mock/B 批？
