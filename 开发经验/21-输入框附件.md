# 21 · 输入框附件：粘贴图片 / 文件 / 文件夹（2026-09-28）

> 用户可见的功能，一次落地。**改这块之前先读第三节的根因** —— 那一节说的是一类
> 「钩子根本没被调到」的坑，不只属于这个功能。

## 一、用户要什么

原话：

> 「请你在图文模式、文本模式和视频模式这三个模式下，让用户的输入框能够粘贴图片、粘贴文件、
> 粘贴文件夹，并把对应的图片、文件或文件夹显示在连续对话这一行的按钮上方，依次显示，也可以
> 点击，显示为缩略图，用户可以左右滑动查看更多缩略图，也可以折叠。这一行的最左侧是一个折叠
> 按钮，用户点击之后可以把这些内容显示在一个列表上，然后展开查看。因为这几个模型都支持图片，
> 也支持这些文件。」

他在两轮问答里额外拍板了四条：

| # | 决定 |
|---|---|
| 1 | **图片给真图片；文件 / 文件夹只给绝对路径**（交给有工具的 agent 自己去读） |
| 2 | 范围 = **文本 / 图文 / 视频**三个模式，**语音模式不做** |
| 3 | 点缩略图 = **在面板里预览**（不是"用系统默认 App 打开"） |
| 4 | 发出去之后附件**仍然留着**，直到用户手动删 |

第 4 条有个直接后果：附件的行为与既有的「参考材料」同一档 —— 只要附件条里还有东西，
之后**每一轮**（包括按住快捷键说的那一句）都会带着它们发出去。

## 二、三模式三路径

| 模式 | 图片 | 文件 / 文件夹 |
|---|---|---|
| 文本 / 图文（主循环） | 追加进 `analyzeImageStreaming(images:)` 的数组（该方法本来就吃多图，协议一个字没改） | 进 `<attachments>` 块（`userPrompt` 的 sections） |
| 文本 / 图文（Claude Code） | **落盘 + 给路径**，靠 claude 自己的读图能力 —— 与 `writeScreenshotForTurn` 同一条既有决定（`--input-format stream-json` 没有官方文档，不许猜 content block） | 同一段前言里给路径 |
| 视频（打字那一轮） | 追加进 `CascadeVoiceEngine` 的 `images` | 同一个 `<attachments>` 块，拼在 utterance 前 |
| 视频（「理解」用实时模型时） | **发不出去**（那条协议只吃文字）→ 记一行 ⚠️ 并如实不假装发了 | 路径是文字，照常进请求 |

**一个顺手查出来的结构事实，值得记住**：这一页的打字发送**从来只走 `CascadeVoiceEngine`**
（`sendText` → `startTurn` → `cascadeEngine.runTurn`，**全双工模式下也一样**，`CascadeVoiceEngine`
里没有任何按引擎分派的代码）。所以附件只要接在三段式那一处，就覆盖了视频模式的全部打字回合。

## 三、根因：`paste(_:)` 根本不会被调到（图片粘贴板时）

**现象**：⌘V 粘图片，屏幕上什么都没有 —— 输入框里没多字符、附件条不出现、日志一行都没有。

**先分清"没调到"和"调到了没认出来"**（这两者的屏幕表现一模一样）。装了两行仪器后量到的：

```
图片在粘贴板时按 ⌘V → 一行日志都没有（连 paste(_:) 的入口都没打印）
纯文本在粘贴板时按 ⌘V → 📎 输入框收到粘贴（类型：public.utf8-plain-text, NSStringPboardType）
                        📎 粘贴未被识别为附件（粘贴板类型：public.utf8-plain-text, NSStringPboardType）
```

**根因**：这个输入框是 `isRichText = false` 的 `NSTextView`，AppKit 因此**不接受图片类的
粘贴板** —— 菜单里的「粘贴」被判为不可用（menu validation），于是 ⌘V 作为**快捷键**根本不会
派发到视图上。`paste(_:)` 只覆盖"纯文本粘贴被调用"的那条路。

**修法**：拦在 `keyDown`（这个类本来就为回车做过一模一样的事）——

```swift
override func keyDown(with event: NSEvent) {
    if handleSendKeyEvent?(event) == true { return }
    if event.keyCode == Self.letterVKeyCode,                  // 9 = v，用码不用字符
       event.modifierFlags.intersection(.deviceIndependentFlagsMask).contains(.command),
       handlePaste?(NSPasteboard.general) == true { return }
    super.keyDown(with: event)
}
```

`paste(_:)` 的覆写**保留**（纯文本那一路仍然由菜单 → `paste(_:)` 走），两条入口共用同一个
`handlePaste` 闭包，所以"收走就不许再插字符"这条规矩只有一处。

**为什么用 keyCode 而不是字符**：`charactersIgnoringModifiers` 受键盘布局与中文输入法影响。

**这一类坑的通用形状**（值得记住）：**一个"永远收不到"的钩子，和一个"收到了但判错了"的钩子，
在屏幕上长得一模一样**。所以仪器要打两处 —— 入口一处、判定一处。这次的入口那一行正是
决定性的证据：它在文本粘贴时打印、图片粘贴时完全不打印。

## 四、实测（2026-09-28 02:0x，真机、当前构建）

**主循环（图文模式）**

| 步骤 | 证据 |
|---|---|
| 粘贴一张截图 | `📎 附件：+1 → 📎 附件：图片 1 张 · 文件 0 个 · 文件夹 0 个`；AX 树出现缩略图 + 最左那颗折叠钮 |
| 粘贴 `/etc/hosts` + `/tmp` | `📎 附件：+2 → 📎 附件：图片 5 张 · 文件 1 个 · 文件夹 1 个`；缩略图读作 `hosts · 文件`、`tmp · 文件夹 · 849 项` |
| 点缩略图 | 面板内预览打开：标题 + `图片 788×678` + ✕ + 「用默认 App 打开 / 在访达中显示 / 移除」 |
| 点最左那颗折叠钮 | 切成列表（5 行 × 26pt），按钮图标变成「显示成缩略图」 |
| 发一条问题 | `📎 附件：图片 5 张 · 文件 1 个 · 文件夹 1 个（随这一轮发给模型）` |
| **模型的回答** | 「那几张图都是 Orca 应用的窗口截图，左侧是「工作、技能、自动化」菜单，右侧是「最近提交」面板。」—— **这段内容只存在于粘贴的图里** |

**Claude Code 卡片（文本模式）**

| 步骤 | 证据 |
|---|---|
| 粘贴一张图 | 附件条出现（同一套） |
| 发一条问题 | `📎 Agent 这一轮的附件图落盘 1 张 → …/Wanna/AgentAttachments` + 每个路径一行 + `📎 附件：图片 1 张 … （随这一轮发给 Wanna）` |
| 落盘文件 | `附件-2026-09-27T18-03-22Z-1-粘贴的图片.jpg`，41,767 字节，`0600` |

⚠️ **那一轮的模型侧没验到**：这台机器上的 claude CLI 自己报
`API Error: 402/403 The free trial quota … has been exhausted`（账户配额，与附件无关）。
App 侧的落盘与前言都发生在 CLI 失败**之前**，所以那条链在 App 这一端是走完的。

**视频模式（全双工 · 全模态 3.8 Flash，摄像头/屏幕关掉、声音关掉）**

| 步骤 | 证据 |
|---|---|
| 切到「视频」 | 附件条仍在（跨模式保留）；切到「语音」**附件条消失**（附件仍在 store 里，只是不画） |
| 连接后粘贴 + 打字发送 | `📎 附件：随这一轮视频对话发给模型（图片 1 张 / 共 1 条）`；请求 `🌐 … 0.3MB, 2 image(s)`（屏幕 1 + 粘贴 1） |
| **模型的回答** | 「你贴的那张图（**640×400**）是 macOS 顶部菜单栏的局部截图：左边是苹果 logo 和「Orca / 编辑 / 查看 / 窗口 / 帮助」菜单项……」—— 连我那张图的**像素尺寸**都说对了 |

**模式闸门**（用户划定的三个模式）也一并验了：文本 / 图文 / 视频都有附件条，**语音没有**。

## 五、已知边界（都不是 bug，是没做）

1. **附件不进历史**：`ConversationHistoryEntry` 没加字段，所以往下翻旧对话看不到当时的附件
   —— 与截图同一条规矩（截图也是只在内存里活一轮）。
2. **上限**：图片 5 张（与 `TurnReferenceMaterials.maximumScreenshots` 同一个数）、总数 20 条。
   到顶会拒绝并**留一行日志**，不静默丢弃。到顶之后**文件仍然进得来**（它只是一条路径）。
3. **视频模式里"说话"那一轮不带粘贴的图**：全双工那条路的图像通道是
   `input_image_buffer.append`（1 张/秒的连续画面缓冲，官方要求先发过音频），语义是
   "当前的画面"，不是"他贴给我的那份材料"。打字那一轮才走附件那条路。
4. **拖拽入框不在此次范围**（用户说的是"粘贴"）。
5. **只有内存**：重启后附件条是空的（用户没说"重启后还要留着"）。

**顺带发现、没有修的两处既有问题**（如实记着，与本功能无关）：

- 输入框右下角那颗 ✕ 在**光标还在框里时**清不干净：它只写 `draft = ""`，而 `updateNSView`
  在编辑中**故意不回写**字符串（那条规则本身是对的，见 `MessageComposerField` 的注释），
  于是占位符出现了、框里的旧字却还在，接着打字就接在旧字后面。
- 视频页那两颗「摄像头 / 屏幕」开关显示的状态与角色里真正生效的值**可以是两回事**：
  我在页面上把它们关掉、界面显示「关着」，但连接后的请求里**照样带了屏幕那一张**
  （`🌐 … 2 image(s)` 就是证据），重启后开关又显示回「开着」。

## 六、改这块之前要知道的

- **附件按卡片 id 存**（与 `AppSettings.cardChatMode`、`cardVoiceRoleIDs` 同一个键），
  真相在 `ComposerAttachmentStore`（`@MainActor` 单例，只在内存）。
- **默认值让不传的调用点一个字都不用改**：`MessageComposerField` 的四个新参数都有默认值，
  所以 `TemporaryConversationOverlay`（不在范围内的临时对话）完全没动。
- **预览面板挂在三个内容列各自的 `.overlay` 上**，状态（`previewingAttachment`）只有一份 ——
  挂在那条 64pt 高的附件条上会**画得出、点不动**（见 `开发经验/10-踩过的坑.md` D14）。
- 界面上"有没有附件条"读的是**卡片模式**，引擎里"发不发"读的是**聊天类型**，
  两者由 `alignChannelForCardMode` 绑在一起 —— 所以"看得见的"与"真的发的"不会分家。
