# 19 · 任务方向看板（鼠标右上角，说话期间显示）

> 用户 2026-09-27 的需求（原文是一份完整的规格，见下面各节的引文）。
> 一句话：**主 Agent 说话的时候，除了刘海下面那行字幕，鼠标右上角还应该有一块板**，
> 告诉他「AI 现在怎么理解你这次要做的事」，并让他点一下确认/否认。右下角那块仍然是结果。

## 一、它长什么样

```
┌─────────────────────────────────────────┐
│ 笔记类  [保存到 Notion   ] ✗  [存成一条录音] ✗ │   ← 3 行 2 列 = 6 个方向
│ 显示类  [指给我看      ] ✗  [圈出来      ] ✗ │      第 1 行笔记类 / 第 2 行显示类 / 第 3 行执行类
│ 执行类  [操作电脑      ] ✗  [派个 Agent ] ✗ │
├─────────────────────────────────────────┤
│ 用户想让我把屏幕上的那段文字存进 Notion。      │   ← AI 的理解（每 3 秒刷新一次）
├─────────────────────────────────────────┤
│ [ 补充说明（会一起发过去）              ] │   ← 用户手打的补充，也一起发过去
└─────────────────────────────────────────┘
```

- **位置**：鼠标**右上角**（`NotchSupport.directionBoardPanelFrame`：左下角 = 鼠标 +12pt，向右上展开，
  夹进屏幕、避开刘海那条带子）。**锚点只在显示那一刻取一次** —— 用户：「位置固定，不随鼠标移动」。
- **宽度与样式与右下角那张结果卡片完全一致**：`AnswerCardView` 的那几个常量与 `cardBackground`
  2026-09-27 放开成 internal，看板读的就是同一份（宽度固定 340）。
- **点文字 = 确认**（文字变绿、叉变对勾）；**点右边的叉 = 否认**（文字与叉整体变红）；再点一次取消。
  已决定的格子**冻住**：AI 之后改不了一格已经被点过的文字（否则他确认的那句话会在他眼前变成另一句）。

## 二、什么时候出现、什么时候消失

**与刘海那行字幕同一个判据**：`NotchPanelModel.notchBandSitsAboveTranscriptLine`
（= `activityPhase == .listening && !isFullscreenSuppressed`），写在
`NotchWindowController.syncListeningTranscriptPanel()` 里一处 —— 两者不可能不一致。

用户的原话：「当用户按住快捷键时，即用户说话时，就持续显示，直到用户按下快捷键发送问题，
或等待 2 秒自动发送问题后才不显示。返回结果之后也不显示，因为返回结果由右下角卡片显示。」

所以：按下快捷键 → 出现；提交（快捷键 / 2 秒静默）→ 收起；结果由右下角那张卡片负责。
刘海面板铺开时**整块不显示**（那块面板盖住全屏，与结果卡片同一条规矩）。

## 三、六格里的文字怎么定：**预设优先，AI 兜底**

用户 2026-09-27 的原话：「如果用户预设的内容没有匹配到，就让 AI 生成；如果用户关键词已经匹配，
就显示用户匹配的内容。因为用户可能会说『保存到 Notion 什么什么页面』，AI 可能识别不了，
所以**以用户提前预设的为准**；如果没有预设，就让 AI 生成。」

展开成三条（`DirectionBoardConfiguration.displayText` 一处实现，视图与"发出去的标签"都读它）：

1. **本地关键词命中** → 整行都用预设短语（命中的那一格高亮绿框）—— **AI 不许覆盖**；
2. **没命中** → **第 1 格**显示 AI 写的短语（≤12 字），第 2 格仍然是预设；
3. **没命中、AI 也说「无」** → 两格都是预设，谁都不高亮。

⚠️ **短关键词只认精确匹配**（4 字以下），这是探针逼出来的：3 字关键词给容错 1 时，
「帮我**点一下**那个发送按钮」会命中笔记类的「**存一下**」—— 点亮错方向，而且本地命中还会
**压掉**那个方向本该由 AI 给的标签。宁可少命中（交给 AI），不许误命中。

## 四、那次请求（每 3 秒一次，文本变了才发）

- **模型**：主 Agent 的 🧠（`BailianVisionChatAPI.analyzeImageStreaming(images: [])`，纯文字、
  自动关推理）；当前活动卡片配了别的 AI 就用那一张（`CompanionManager.visionRoleOverride(forCardID:)`）。
- **系统提示词**：`CompanionManager.directionBoardSystemPrompt(for:)` = **主 Agent 那份逐字相同**
  + 一节「怎么把理解结果写成看板要的格式」。用户：「以保证 100% 模拟主 Agent 的思考方式」。
  ⚠️ 那一节**只加在这次请求上**，真正回答用户的那一轮不带它。
- **用户消息**：`<transcript>` 当前识别文本 + 六个预设短语（让模型用词一致）+ **只列本地没命中的行**。
- **节奏**：每 3 秒看一次，**只有识别文本跟上次发出去的不一样才真发**（用户在我问「3 秒一发 vs
  文本变了才发」时选了后者）；同时最多一个请求在飞；代次计数丢弃过期回复；失败保留上一次的结果。
- 闸门收在纯函数 `DirectionBoardSession.shouldRequest(...)` 里（会话本身脱离 App 编不起来，
  收成纯函数探针才能把五条各试一遍）。

### 解析：认不出来的行一律并进正文

模型被要求回：

```
<<<看板
说明：<一到两句，≤200 字>
方向1：<≤12 字；不适用写「无」>
方向2：…
方向3：…
看板>>>
```

规则（每条都有断言，`DirectionBoardPrompt.parseResponse`）：只认 `说明:` / `方向N:` 开头的行
（全角冒号、`**说明**：`、代码块都认）；值取**第一个**冒号之后；同键重复**先到者胜**；
「无/-/空」= 这一行没有标签；**其余每一行都并进说明** —— 多写的、少写的、被截断的都不会丢，
也不会被当成标签；完全不成形时保留上一次的说明（绝不把正文清空）。

⚠️ **标签上限 12 字，不是 8**：用户自己的预设短语里「保存到 Notion」是 10 字、
「派个 Agent 去做」是 11 字，模型很可能原样回一个预设 —— 8 字上限会把它截成「保存到 Noti」，
而且**是静默的**（屏幕上只是少了一个字母）。探针抓到的。

## 五、提交时那几行（注入）

用户：「将记录内容作为标签追加到用户提示词的前一行，格式为「用户真实意图的任务方向是：XXX」，
下方再接用户原始提示词。输入框中用户手动输入的内容 → 同样作为标签追加进去。未点击的项不追加标签。」

```
<user_intent_tags>
用户真实意图的任务方向是：保存到 Notion
用户真实意图的任务方向是：指给我看
用户的补充说明是：顺便截图
</user_intent_tags>

the user just said, out loud: 帮我把这段存起来看看
```

两处分寸：

1. **只写点过确认的**（没点的、点否认的都不写；输入框为空就整段不出现）；
2. **只进发给模型的提示词**，不进历史、不进界面上那两颗气泡 —— 会话记录里仍然只有用户自己说的话。
   所以它单独一个 `<user_intent_tags>` 块，**不塞进 "the user just said, out loud:" 里**：
   那几行不是他嘴里说的，是他在看板上点的。

**取走只在一处**：`sendTranscriptToVisionChatWithScreenshot` 的开头（四条提交路径全部经过它：
快捷键发送 / 2 秒静默 / 确认模式轻点 / 连续追问），所以不可能漏一条、也不会取两次。
其余"这一轮结束了但没发送"的路（ESC 打断正在听、追问窗口关闭、空转写）都显式取走丢掉 ——
否则他点过的方向会跟到下一次**打字**提问上。

## 六、怎么验（哪些机器能验、哪些必须人来）

**机器能验的（本仓的探针法）：**

- **纯逻辑**：`/tmp` 里的独立探针（只编 3 个源文件、不启动 App）**70 条断言**全过 ——
  配置解析、关键词表（六个短语的种子各自命中正确的行与列、无关句子不命中、2 字关键词不误报）、
  解析器全套畸形输入、注入拼装、以及**节奏闸门五条**。
  仓库里 `WannaTests/DirectionBoardTests.swift` 是同一批（`build-for-testing` 通过编译；
  **跑测试要退掉正在用的那个 App**，因为测试宿主就是 App 本身）。
- **界面**：离屏渲染探针（`NSHostingView` + 出 PNG + 采样像素）验看板与设置节的排版、
  三行顺序、确认/否认的颜色。
- **真机（自检开关）**：`WANNA_DIRECTION_BOARD_SELFCHECK=1`（先例 `WANNA_DESKTOP_AGENT`）
  在没有麦克风的情况下把看板拉起来、喂几句假转写、**默认不发任何请求**。
  实测（进程 16565）：面板 Quartz `(303,592,340×186)` —— 左下角正好在鼠标 +12pt ✓；
  三行顺序与六个短语各就各位 ✓；假转写让「保存到 Notion」「指给我看」自己亮了绿框 ✓；
  AX 点文字 → 绿字 + 对勾，点叉 → 红字 + 红叉 ✓；两次点击后面板 frame 一个像素没动 ✓；
  **显示看板没有抢走前台 App**（前台仍是 Orca）✓；输入框点一下能收键盘 ✓。

**必须人来验的：** 真说话时看板出现、正文随说的话更新、提交后收起、以及
「每 3 秒一次、只在文本变多时发」的手感 —— 这台机器没有可用的语音输入
（音箱→麦克风耦合 212–447/32768，门槛是 0.25）。

## 七、文件与开关

| 文件 | 作用 |
|---|---|
| `DirectionBoardSettings.swift` | 配置（3×2）+ 出厂值 + 本地匹配 + 校验（手改 JSON 后仍能画）+ `displayText` |
| `DirectionBoardPrompt.swift` | 追加在主 Agent 提示词后的那一节 + 请求消息 + 解析 + 注入拼装 |
| `DirectionBoardSession.swift` | 状态机（单例，形状照 `NotionNoteSession`）：节奏、请求、点过的格子、自检开关 |
| `DirectionBoardView.swift` | 那三段界面（复用结果卡片的外壳常量） |
| `DirectionBoardPanelController.swift` | 可点击面板（配方 = `AgentHUDController` + `NotchListeningTranscriptPanel` 的 `canBecomeKey`） |
| `DirectionBoardSettingsView.swift` | 设置 → 操作 → 「任务方向看板」一节（总开关 + 六个短语 + 六组关键词 + 恢复默认） |

开关：`AppSettings.directionBoardEnabled`（总开关，关掉之后**面板不出现、请求也不发**）与
`AppSettings.directionBoard`（六个短语与关键词）。两者都在设置页可改，且随「保存」落盘。

**它不碰任何别的状态**：不改 `currentResponseTask` / `voiceState` / 历史 / TTS / 截图 ——
唯一的输出就是"提交时加在提示词前面的那几行"。
