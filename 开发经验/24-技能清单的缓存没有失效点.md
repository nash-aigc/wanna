# 技能清单的缓存没有失效点（2026-09-29）

## 现象

用户要求收一遍技能描述。我改完 6 份 `SKILL.md` 的 frontmatter，跑 `list_skills` 验证 ——

**返回的还是旧描述，字符数一个不差（2272）。**

屏幕上没有报错，日志里没有异常，文件确实改对了（`grep` 得到新描述）。
**看起来像"我的修改根本没写进去"。**

## 根因

`Wanna/SkillCatalog.swift`：

```swift
private static var cachedSkills: [SkillDefinition]?
static func allSkills() -> [SkillDefinition] {
    if let cachedSkills { lock.unlock(); return cachedSkills }   // ← 命中就永不重读
    ...
    lock.lock(); cachedSkills = loaded; lock.unlock()
}
static func invalidateCache() { lock.lock(); cachedSkills = nil; lock.unlock() }
```

`invalidateCache()` **在整个仓库里一个调用点都没有**（`grep -rn` 六处同名方法，
只有这一个没人调）。所以它是**"启动读一次、之后永远不变"**。

改技能描述 → 不重启 Wanna → 永远看不到变化。

## 判据（下次怎么快速认出来）

**"文件改了、程序里还是旧的" → 第一反应查缓存有没有失效点**，
而不是怀疑自己没写进去。判据很简单：**那个 `invalidateCache()` / `clearCache()`
有人调吗？** 一条 `grep -rn` 就有答案。

这和本仓的 `ModelConfigurationStore` / `AppSettingsStore` 那几个 store **形状不同**：
那些是**故意**缓存的，而且改动走 store 自己的 `save()`，缓存由写入方维护。
`SkillCatalog` 是**只读外部文件**的目录扫描 —— 文件可能被任何人在任何时刻改
（用户手改、我改、技能作者改），**没有任何"写入方"能来失效它**。
所以它根本不该缓存，或者必须在每次读之前失效。

## 修法（极简）

`WannaMCPTools.listSkills()` 里加一行 `SkillCatalog.invalidateCache()`，
再 `allSkills()`。理由两条：

1. 技能目录只有十来个文本文件，现读是毫秒级；
2. 这个函数在整条流程里**只在 Python 启动时调一次**（`wanna_agent.py` 启动时拉一次
   塞进系统提示词），缓存本来也省不下什么。

## 同一个改动里，另一件值得记的

**改了技能描述必须重启 App** —— 不是 bug，是"改代码要重启"那条规矩的延伸：
技能描述虽然住在**数据文件**里，但读它的 `SkillCatalog` 在**代码**里跑，缓存也在代码里。
所以它**不属于** CLAUDE.md 里那条「改 `AppSettings.json` 不用重启」的例外。
（这条例外只对**由 store 维护、自带通知**的数据成立。）

## 验证

改完 → 全量 typecheck 0 error → `BUILD SUCCEEDED` → `ditto` 整包同步 →
重启（PID 29363）→ `list_skills` 返回 **1306 字符**（原 2272，−43%），11 条全是新描述。
